# 传统历法日历系统

这是一个简单、稳定、容易维护的传统历法 Web 日历。第一阶段已经完成可运行的公历月历；农历、四柱、节气、真太阳时和十二值星将在后续阶段实现，当前页面不会显示伪造结果。

## 当前功能

- 完整公历月历，支持月份和年份切换。
- 点击日期查看详情，并可随时返回今天。
- 自动适应手机、平板和电脑。
- 自动跟随系统浅色 / 深色模式。
- 自动读取 `配置/` 中全部中文 TXT 规则文件。
- 配置错误会记录文件名、行号和原文，不会导致网站崩溃。

## 本地运行

需要 Node.js 20.19 或更高版本。

```bash
npm install
npm run dev
```

执行自动测试和正式构建：

```bash
npm test
npm run build
```

## 维护传统规则

传统规则仍然只维护在 `配置/` 目录的中文 TXT 文件中，不需要修改 JSON 或程序代码。编辑后重新构建网站即可生效。

## 资料与规则

- `开发规则.md`：项目的基础开发规则与算法边界。
- `GPT项目提示词.txt`：可直接放入 GPT 项目的长期提示词。
- `待确认规则.md`：目前存在冲突、缺项或需要后续确认的传统规则。
- `配置/`：全部采用中文文件名和中文自然语言格式，方便人工维护。

## 配置文件基本规则

1. 配置文件统一使用 UTF-8 编码。
2. `#` 开头的行是备注，程序应忽略。
3. 空行应忽略。
4. 中文冒号 `：` 为推荐格式，同时允许英文冒号 `:`。
5. 一条错误配置不得导致整个系统崩溃。
6. 配置错误时，应明确提示：文件名 + 行号 + 原始内容。
7. 不使用 JSON、数据库或复杂配置格式作为人工维护入口。
8. 配置文件是传统规则的主要数据源，底层历法算法仍写在程序代码中。

## 重要说明

- 公历、农历、二十四节气、四柱、真太阳时、十二值星属于底层算法，不放在这些 TXT 规则文件里。
- 农历月与节气月必须严格区分。
- 神圣纪念日按农历月日匹配。
- 所有“时”规则统一使用系统最终得到的时辰；定位成功时优先用真太阳时，定位失败时使用北京时间。
